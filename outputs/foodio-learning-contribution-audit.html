What you appear to have actually learned

Learning is credited only when the history shows you reasoning, restating, correcting, or writing before review. Merely asking for an explanation after ChatGPT implemented a feature counts as exposure, not mastery.

Demonstrated learning

  • Request and response flow: form state, fetch, route parsing, service work, status codes, and JSON response handling.
  • Authentication versus authorization: a valid profile is not automatically allowed to control a restaurant.
  • One identity with multiple roles: a person can be a customer and later gain restaurant-owner or delivery roles.
  • Database result shaping: selected columns return row objects, and map converts those rows into an array of role values.
  • Server and client boundaries: server code loads identity, while click handlers, browser APIs, and client navigation need client components.
  • Transactions: restaurant creation and owner membership must succeed or fail together.
  • HTTP response structure: the JSON body and response options such as status and headers are different layers.
  • Product decomposition: separate onboarding forms can save independently under one restaurant ID.

Not yet demonstrated independently

  • Building a third-party browser integration from documentation without ChatGPT translating the docs into the exact component.
  • Implementing an end-to-end feature without repeated “check” cycles and exact correction prompts.
  • Reconstructing JWT, OTP, or restaurant authorization from a blank editor.
  • Diagnosing runtime UI and asset failures without ChatGPT or browser automation doing the investigation.
  • Designing a secure resource-scoped authorization layer without AI proposing the membership query and failure behavior.
  • Owning the test strategy. Most evidence comes from checks run by ChatGPT, not tests you designed and executed independently.

What you can honestly claim

An older FoodIO report used the wording “I wrote the FoodIO implementation, and Codex reviewed it.” That was defensible for parts of the earlier auth learning loop. It is no longer accurate for the project as a whole after the later OTP, onboarding, multi-restaurant, and Leaflet implementations.

Recommended wording:
“I am building FoodIO as an AI-assisted learning project. I own the product direction and have written meaningful parts of the authentication and role flows through an iterative review process. I also used ChatGPT for architecture, debugging, verification, and some complete feature implementations, including the recent map and parts of restaurant onboarding. I am now changing the workflow so I implement first and use AI as a reviewer.”

Safe claims

  • You understand more about auth, roles, requests, responses, joins, and React boundaries than when you started.
  • You contributed real product thinking and some implementation.
  • You used AI actively, questioned it, rejected incorrect outcomes, and iterated.
  • You can explain several FoodIO flows with support from the code.

Claims to avoid

  • “I designed and built the complete architecture myself.”
  • “ChatGPT only reviewed my code.”
  • “I know how to build the map picker because it works in the repository.”
  • “Every committed feature represents knowledge I can reproduce.”

How to prove the learning is yours

The next milestone should not be another large feature. It should be evidence that you can perform the reasoning without ChatGPT carrying it.

  1. Trace before coding. Explain the current restaurant creation request from page to database transaction in your own words, without asking ChatGPT for the answer.
  2. Design one section yourself. Choose the basic-information section. Write its route, authorization checks, data contract, schema changes, and save behavior as a short plan.
  3. Read only the relevant official docs. Do not ask ChatGPT for code. Record what each doc changes in your plan.
  4. Implement the vertical slice. Build it from a blank editor or existing patterns. Run your own typecheck and browser test. Save the failures you encounter.
  5. Ask ChatGPT for review only. The prompt should be “inspect my implementation and report defects, do not edit.”
  6. Repair it yourself. Ask for hints only when the failure remains after your own diagnosis.
  7. Rebuild one critical function later. A week later, recreate a small JWT verifier, membership authorization query, or location-selection callback without copying FoodIO.

Passing condition: You can explain, implement, debug, and verify one complete FoodIO slice with ChatGPT acting only as reviewer. Until then, you have learned with support, but independence remains unproven.
